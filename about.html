About CertiVault

CertiVault — Secure Cloud Certificate Locker using AWS S3 & IAM. An IBM Cloud Computing internship project.

Purpose

Students and professionals collect certificates from internships, courses, and colleges throughout their careers, but usually store them scattered across email attachments, phone galleries, and random folders. CertiVault gives every certificate a single, organized, cloud-secured home that can be searched, filtered, and accessed from anywhere.

Problem

Certificates are frequently lost, misplaced, or hard to find when needed most — for job applications, higher-education admissions, or verification requests. There is no lightweight, purpose-built tool for managing just certificates the way there is for photos or documents in general.

Solution

CertiVault provides a dashboard, upload flow, searchable gallery, and profile view — all backed conceptually by Amazon S3 for storage and AWS IAM for access control. Certificates are tagged by category (Internship, Academic, Achievement) so they're easy to browse and retrieve.

AWS Implementation

Amazon S3 Bucket. A bucket named something like certivault-user-storage is created in an AWS region (e.g. ap-south-1). Each uploaded certificate becomes an "object" inside the bucket.

Folder structure. Objects use key prefixes to simulate folders:

  • certivault-user-storage/internship/
  • certivault-user-storage/academic/
  • certivault-user-storage/achievement/

Bucket policy. The bucket is kept private — public access is blocked at the bucket level. A bucket policy restricts actions to a specific IAM identity rather than "*" (everyone):

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": { "AWS": "arn:aws:iam::<account-id>:user/certivault-app-user" },
      "Action": ["s3:PutObject", "s3:GetObject", "s3:DeleteObject"],
      "Resource": "arn:aws:s3:::certivault-user-storage/*"
    }
  ]
}

Object upload/download. The app requests a pre-signed URL from the backend, which lets the browser upload (PUT) or download (GET) directly to/from S3 for a short time window — without exposing AWS credentials to the browser.

Public vs private bucket. A public bucket allows anyone with the URL to read objects — never appropriate for personal certificates. CertiVault's bucket stays private; only the app's IAM identity, using signed requests, can read or write objects.

IAM User, Policy & Least Privilege

IAM User: a dedicated identity (certivault-app-user) is created for the application — never the AWS root account.

IAM Policy: a JSON document lists exactly which actions are allowed:

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject", "s3:DeleteObject", "s3:ListBucket"],
      "Resource": [
        "arn:aws:s3:::certivault-user-storage",
        "arn:aws:s3:::certivault-user-storage/*"
      ]
    }
  ]
}

Least Privilege Principle: the policy grants only upload, download, delete, and list actions on this one bucket — nothing else in the AWS account. If these credentials were ever leaked, the damage is contained to this single bucket.

Future Scope

  • Replace simulated login with real AWS Cognito authentication.
  • Connect the upload/download flow to a live S3 bucket using pre-signed URLs.
  • Add AWS Lambda to auto-generate thumbnails for uploaded certificates.
  • Use Amazon CloudFront as a CDN for faster certificate previews.
  • Add email notifications via Amazon SES when a certificate is uploaded.
